# Калькулятор очков «Тысяча» — личная версия
Справочник правил и модель данных для разработки (Kotlin / Android Studio).
Цель приложения: **не разыгрывать игру**, а быть счётчиком-помощником, который знает все правила компании и сам считает очки, штрафы и состояния игроков. Карты каждый разыгрывает вживую.

---

## 1. Настройки (переключаемые пользователем)

| Настройка | Значения |
|---|---|
| Количество игроков | 3 или 4 |
| Уход в минус | вкл / выкл |
| Правило сдвига колоды | вкл / выкл |

Всё остальное — хардкод, единое для всех партий:
- Правило 555 — всегда включено.
- Тузовый марьяж — всегда включён, 200 очков.
- Стоимость обычного марьяжа: ♠40 ♣60 ♦80 ♥100.
- Правило бочки (880) — всегда включено.
- Правило прочерков — всегда включено.
- Правило росписи — всегда включено, лимит 3 за партию.

---

## 2. Роли и ротация

- Раздающий (дилер) назначается игрой и сдвигается по кругу каждый кон. Игра просто отображает, кто сейчас раздаёт — руками игрок ничего не выбирает.
- **При 3 игроках:** играют все трое, торгуются за общий прикуп как обычно. Если прикуп никто не взял — он остаётся «ничейным», кон разыгрывается без него.
- **При 4 игроках:** реально в кону играют только 3 человека — все, кроме раздающего. Раздающий в этом кону — фактически наблюдатель: он раздаёт, смотрит свою собственную долю (не общий прикуп, отдельная от него величина) и записывает её очки только себе. На торговлю и игру остальных троих он никак не влияет; общий прикуп между оставшимися тремя разыгрывается как в обычной игре на троих.

---

## 3. Ритуал сдвига колоды (если включён)

Раздающий даёт сдвинуть колоду игроку справа и смотрит нижнюю карту:

- **9** → сдвигает ещё раз. Счётчик девяток +1.
- **J (валет)** → карта убирается в центр, смотрится следующая. Счётчик валетов +1.
- Любая другая карта → ритуал закончен, раздача идёт как обычно.

Счётчики независимы и **не сбрасывают друг друга** (последовательность 9, J, 9, J, 9 = 3 девятки + 2 валета, а не «прервано»).

- За каждые **полные 3 девятки** — тот, кто сдвигал (игрок справа от дилера), получает **−120**. Может повторяться (6 девяток = −240 и т.д.).
- За каждые **полные 3 валета** — сам раздающий получает **−120**.

---

## 4. Правило 555

Если накопленный счёт игрока попадает ровно на **+555** или **−555** — счёт сбрасывается до **0**.

---

## 5. Правило бочки (880)

- Порог 880 — «стена», проскочить нельзя: если новое начисление должно перевести игрока за 880, счёт фиксируется ровно на **880** (излишек сгорает), игрок «встаёт на бочку».
- После этого у игрока есть **3 последующих кона** (считаются по порядку игры, независимо от того, торговался он в них или нет), чтобы набрать достаточно очков и пробить 880 насквозь.
- Если за эти 3 кона порог не пробит — списывается **−120**. После штрафа счёт игрока естественным образом падает ниже 880, и он снова в обычном режиме игры.
- Если за эти 3 кона игрок пробивает 880 — бочка снимается, игрок продолжает нормально копить очки выше порога.
- Смысл правила: пока игрок на бочке, каждый кон «тикает» его лимит — это мотивирует торговаться и рисковать даже с слабыми картами.

---

## 6. Правило прочерков

- У каждого игрока свой счётчик «−» (прочерков) за всю партию — **не обязательно подряд**.
- При достижении **3 прочерков** — счётчик обнуляется, игрок получает **−120**.
- Прочерки у каждого игрока отображаются в интерфейсе постоянно.

---

## 7. Правило росписи

- Лимит: **3 росписи за партию** (общий, не по игрокам).
- Игрок, выигравший торг и взявший прикуп, может расписаться **после того как посмотрел прикуп, но до начала розыгрыша карт**.
- При росписи:
  - ставка делится **пополам**, округляется до 5;
  - эта половина начисляется **каждому из двух игроков, которые не взяли прикуп** (то есть двум другим из тройки, реально игравшей в этом кону);
  - сам расписавшийся **ничего не теряет**;
  - ход/раздача передаётся дальше как обычно.

---

## 8. Ввод очков за кон

- Значения очков вводятся дилером после розыгрыша: числа округляются **до 5** (например, 120, 35, 90).
- Вместо числа можно поставить **прочерк «−»** — см. правило 6.
- При 4 игроках раздающий получает отдельно засчитанные очки своей доли — вводятся туда же, в общую таблицу кона, отдельной колонкой/полем.

---

## 9. Черновик модели данных

```kotlin
data class GameSettings(
    val playerCount: Int,              // 3 или 4
    val allowNegativeScore: Boolean,
    val cutRitualEnabled: Boolean
    // 555, тузовый марьяж, бочка, прочерки, роспись — хардкод, не хранятся как настройка
)

data class Player(
    val id: Int,
    val name: String,
    var totalScore: Int = 0,
    var dashCount: Int = 0,            // прочерки за игру
    var isOnBochka: Boolean = false,
    var bochkaAttemptsLeft: Int = 0    // считается только когда isOnBochka = true
)

data class CutRitualResult(
    val ninesCount: Int,
    val jacksCount: Int,
    val cutterPenalty: Int,            // -120 * (ninesCount / 3)
    val dealerPenalty: Int             // -120 * (jacksCount / 3)
)

data class RoundEntry(
    val playerId: Int,
    val rawScore: Int?,                // null, если прочерк
    val isDash: Boolean,
    val isDealerShare: Boolean,        // только для 4-й игрок в режиме "наблюдатель"
    val hasMarriage: Boolean = false,
    val hasAceMarriage: Boolean = false
)

data class RospisEvent(
    val roundNumber: Int,
    val playerWhoTookPrikup: Int,
    val stakeAmount: Int,
    val splitAmount: Int               // stakeAmount / 2, округлено до 5
)

data class GameRound(
    val roundNumber: Int,
    val dealerId: Int,
    val cutRitualResult: CutRitualResult?,   // null, если правило выключено
    val entries: List<RoundEntry>,
    val rospis: RospisEvent? = null
)

data class GameSession(
    val settings: GameSettings,
    val players: List<Player>,
    val rounds: MutableList<GameRound> = mutableListOf(),
    var rospisUsedCount: Int = 0,      // лимит 3 на партию
    var dealerIndex: Int = 0           // текущий раздающий, сдвигается по кругу
)
```

## 10. Модули логики (domain-слой)

| Класс | Отвечает за |
|---|---|
| `DealerRotation` | сдвиг дилера по кругу, определение прикуп-игрока при 4 игроках |
| `CutRitualEngine` | обработка алгоритма сдвига колоды и штрафов за 9/J |
| `Rule555` | проверка попадания на ±555 и сброс до 0 |
| `BochkaEngine` | фиксация на 880, отсчёт 3 попыток, штраф −120 |
| `DashTracker` | накопление прочерков, сброс + штраф −120 |
| `RospisEngine` | проверка лимита 3, деление ставки пополам с округлением до 5 |
| `ScoreRoundingUtil` | округление введённых очков до 5 |

## 11. Экраны (минимум для защиты — 3, реализовано с запасом)

1. **Настройки** — количество игроков, минус да/нет, сдвиг да/нет.
2. **Калькулятор / ввод кона** — кто сейчас дилер, ввод очков по игрокам (или прочерк), кнопка росписи (если применимо), автоматическое применение всех правил после ввода.
3. **История** — список конов, накопленный счёт, статус бочки/прочерков по каждому игроку, использованные роспись.
